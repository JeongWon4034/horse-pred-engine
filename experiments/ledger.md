# 실험 장부

한 실험 = 한 줄. 같은 자(팀 하네스 `data/model/common.py` → `C.report()`)로 잰 것만 적는다.
비교는 valid. test 는 이미 1회 개봉됨(팀 `docs/model/README.md` §3) — 다시 열지 않는다.

- 데이터 기준 커밋: `f17ca36` (팀 origin/develop, schema v2.2.0, 2026-09-02) — `bash pipeline/sync_dataset.sh` 출력
- seed: 20260901 (LightGBM 재현은 팀 값 seed=0 그대로)
- 장치: RTX 4070 Laptop 8GB, torch 2.14.0+cu130. DL 은 `CUBLAS_WORKSPACE_CONFIG=:4096:8` + deterministic 모드
- 콘솔: `PYTHONUTF8=1` (Windows cp949 에서 `C.report()` 출력이 깨진다)
- 전처리 조건: `C.load()` 는 `usable()`(배당 없는 경주 제외)만 적용하고 `schema_v2.clean()` 은 부르지 않는다. 그래서 `X_grade` 41레벨·`F2_sire_id` 의 `'-'` 가 그대로다. LightGBM 과 같은 조건을 유지하려고 DL 쪽도 clean 을 끼워 넣지 않는다 (임베딩 사전에서 `'-'`·결측 → `<unk>` 로만 흡수)
- logloss / ECE / Brier: 행 점수를 경주 내 softmax(온도 1)로 확률화해 계산. 시장 행의 값은 `-mkt_rank` 를 점수로 쓴 것이라 척도 의미가 없어 적지 않는다
- epoch 선택: valid top-1 최고 epoch (LightGBM 의 200라운드도 valid 로 정한 값 — 조건 대칭). valid 숫자는 그만큼 낙관적이다
- 결정성 기준: S1(선형)은 같은 명령 2회 top-1 차 < 0.1%p. S2 이후는 임베딩 backward 가 비결정이라 seed 3개 평균±sd 를 단계당 1회 적는다
- game ROI: `model.backtest` — 시장(인기 1위마) 단승 1단위 ROI **−20.7%** (3,687경주, 적중 37.3%, 적중 평균배당 2.12). 팀 EDA −21.4% 와 일치. 모델 ROI 는 S5 에서

### 판정

- **top-1 로는 어느 단계도 LightGBM 을 "이기지" 못했다.** 넘어야 할 선 35.7 미달, 모든 paired CI 가 0 을 품는다. 표 데이터에서 GBDT 가 강하다는 정설과 일치.
- **S3 전적 시퀀스가 유일하게 일관된 우위를 보인 축은 logloss 다.** seed 3개 전부 LGB 보다 낮고(1.854~1.877 vs 1.885), F1 집계 피처를 전부 빼도 같은 성능 → "과거를 평균으로 뭉개지 않고 순서대로 읽는 것"이 GBDT 가 못 하는 일을 한다는 근거. 분해: 뚜렷한 경주(+3.6%p)·12두 이상(+2.9%p)에서 앞서고 장거리(152경주)에서 뒤진다.
- **S4 경주 내 attention 은 S3 위에서 얻는 것이 없었다.** top-1 −0.56%p, logloss 악화. 이 데이터 규모(3.6만 경주)에서 416k 파라미터는 과적합(ep6~11 에서 조기중단). topk=3 손실은 top-3 만 올린다(64.8).
- **77피처(게임 모드)에서는 S1~S4 전부 LGB 를 SE 안에서 웃돈다**(39.4~39.9 vs 38.9). 확정배당이 이미 답의 대부분을 안고 있어 시장 39.3 을 넘는 건 의미가 작다.
- 방향: 본선 모델 후보는 **S3 history L=20, seed 5개 확률 평균**(logloss 1.8464 최저) 또는 **그것과 LGB 의 5:5 앙상블**(top-1 35.3, LGB 대비 +1.36%p CI [−0.08, +2.79]). S4 는 채택하지 않는다.
- seed 10회(L10·L20) 전부 logloss 가 LGB 보다 낮았다. top-1 은 10회 중 9회 LGB 이상. "확률 품질에서 일관되게 낫다"는 표현은 이 근거로 쓴다.

### 판정

1. **시퀀스는 top-1 에 기여하지 않는다.** L=0 대비 짝 비교가 전부 0 을 품고, L=5·10·30 은 **부호가 음수**다. 이력을 아예 비워도 적중률이 떨어지지 않는다. "과거를 순서대로 읽어 적중률을 올린다"는 서술은 근거가 없다.

2. **logloss 에는 기여한다. 다만 전부는 아니다.** LightGBM 1.8899 대비 seed 평균 격차:

| | logloss | vs LGB |
|---|---:|---:|
| L=0 (시퀀스 없음) | 1.8735 | −0.0164 |
| L=20 (채택) | 1.8490 | −0.0410 |

   즉 **전체 우위 0.0410 중 0.0246(60%)가 시퀀스에서 나오고, 나머지 0.0164(40%)는 시퀀스 없이도 나온다**(임베딩·MLP·PL 손실·seed 평균의 몫). 시퀀스가 유일한 원천은 아니다.

3. **이득의 대부분이 최근 5출전에서 나온다.** L=5 로 이미 1.8525 이고 L=30 은 1.8493 — 25출전을 더 읽어 얻는 것이 +0.0032 다. L=20 이 최소(1.8490)지만 L=5 와의 차는 잡음 수준. **"과거를 길게 읽는 것"이 강점이라는 서술도 근거가 약하다.** 실제로 쓰는 것은 최근 5경주다.

4. **개별 seed 로 보면 L=0 의 logloss(1.8884)가 LightGBM(1.8899)과 사실상 동률**이고 편차가 크다(±0.0123, 다른 L 의 2배). 첫 seed 는 ep2 에서 조기중단됐다. 이력이 없으면 학습이 불안정해진다는 신호로 읽힌다.

### 팀 전달 — `common.py` 의 `report()` 가 틀린 표준오차를 찍는다

`data/model/common.py:128-137` 에서 `se` 를 루프 안에서 덮어쓰므로 **마지막 행의 표준오차가 출력된다.** `with_baselines=True`(기본)이면 마지막 행이 **무작위(10.2%)** 라서, 모델을 판정하는 자리에 무작위 기준선의 SE 가 찍힌다.

```
with_baselines=True   → ±0.85%p    ← sqrt(0.102·0.898/1254). 무작위의 SE
with_baselines=False  → ±1.33%p    ← sqrt(0.335·0.665/1254). LGB 의 SE
```

**이 프로젝트의 "넘어야 할 선 35.7"이 ±0.85 에서 나온 값이다.** 모델 적중률(33~35%)의 절대 SE 는 ±1.33%p 이므로, 같은 논리를 일관되게 적용하면 선은 33.49 + 2×1.33 = **36.2** 가 된다.

- **결론은 바뀌지 않는다.** 두 모델을 같은 경주에서 비교하는 올바른 도구는 짝 비교이고(`evaluate.compare`), 그쪽은 이미 전부 "차이 없음"이다. 선이 더 높아지면 판정이 더 보수적이 될 뿐이다.
- 다만 **발표·문서에 쓰는 ±0.85%p 는 근거가 잘못된 숫자**다. 절대 SE 를 쓸 자리에서는 ±1.33%p 로, 두 모델 비교에서는 짝 비교 CI 로 바꿔 적어야 한다. 건모님 문서(`dataset-2004ext/README.md` §4-2)도 절대 SE 를 ±1.38%p 로, 쌍체 SE 를 ±0.5%p 로 구분해 쓰고 있어 그쪽과도 어긋난다.
