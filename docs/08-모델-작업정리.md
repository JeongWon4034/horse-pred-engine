# 모델 파트 작업 정리 (이정원)

> 2026-09-08 기준. 무엇을 했고, 무엇이 됐고, 무엇이 안 됐는지.
> 숫자는 전부 팀 채점기(`docs/model/common.py`)로 잰 것이고, 근거는 실험 장부에 남아 있다.
> 데이터 기준 커밋 `f17ca36` (schema v2.2.0).

## 1. 개요

경마 예측을 **분류가 아니라 랭킹 문제**로 풀었다. "이 말이 1등 할까"가 아니라
"이 경주 12마리 중 누가 앞설까"를 한 번에 푼다.

팀의 LightGBM 기준선을 재현한 뒤, 딥러닝을 4단계로 쌓으며 **각 단계가 무엇을 더하는지**
같은 자로 측정했다. 목표는 "딥러닝이 좋다"를 보이는 것이 아니라 **어느 구조가 실제로
기여하는지 가려내는 것**이었다.

| 구분 | 내용 |
|---|---|
| 학습 데이터 | 36,586경주 385,514행 (2010-01 ~ 2025-11) |
| 검증 | valid 1,254경주 (2025-11 ~ 2026-05) |
| 최종 평가 | test 802경주 — **미개봉** |
| 프레임워크 | PyTorch 2.14 (CUDA 13), RTX 4070 Laptop |
| 학습 시간 | 단계당 20~80초 |
| 채택 모델 | S3 `HistoryRanker` (파라미터 116,354개) |

## 3. 무엇을 만들었나 — 단계별

각 단계는 앞 단계 위에 부품을 하나씩 얹은 것이다. 전부 PyTorch 표준 레이어다.

| 단계 | 더한 것 | 파라미터 | 결과 | 채택 |
|---|---|---:|---|---|
| S1 | 선형 결합 (조건부 로지스틱) | 153 | 33.6% | 기준점 |
| S2 | 기수·조교사·부마 임베딩 | 59,265 | 34.0% | — |
| **S3** | **말별 직전 20출전 GRU** | **116,354** | **34.8%** | **채택** |
| S4 | 경주 내 Transformer 2층 | 415,875 | 34.4% | 기각 |
| S5 | 6축 타워 + 랜덤 가중치 학습 | — | 34.9% | 슬라이더용 |

**S1 은 경마 예측의 고전 방식(Benter 1994)이다.** 이걸 먼저 재현해 파이프라인이
정상인지 확인하고, 그 위에 쌓았다.

**S3 가 유일하게 기여했다.** 말의 과거를 평균으로 뭉개지 않고 순서대로 읽는다.
"최근 3경주 평균 2등"은 1·2·3등이든 3·2·1등이든 같은 값이지만, GRU 는 그 차이를 읽는다.

## 4. 결과 — valid 1,254경주 (73피처 = 배당 없는 실전 조건)

넘어야 할 선: LightGBM 34.0 + 표준오차 2배 = **35.7**

| 모델 | 1등 적중 | 3착 이내 | 확률 품질 | LGB 대비 (95% 신뢰구간) |
|---|---:|---:|---:|---|
| 시장 (인기 1위마, 참고) | 39.3% | 69.3% | — | — |
| LightGBM 73 (기준) | 34.0% | 63.2% | 1.885 | — |
| S1 선형 | 33.6% | 64.0% | 1.902 | −0.4 [−2.1, +1.3] |
| S2 임베딩 | 34.0% | 64.0% | 1.885 | +0.0 [−1.9, +1.8] |
| **S3 전적 GRU** | **34.8%** | 64.3% | **1.846** | +0.8 [−1.2, +2.8] |
| S4 어텐션 | 34.4% | 63.0% | 1.902 | +0.5 [−1.6, +2.7] |
| S3 + LGB 앙상블 | 35.3% | 64.0% | 1.852 | +1.4 [−0.1, +2.8] |

**표준오차 ±0.85%p.** 모든 신뢰구간이 0 을 품는다 = 적중률 차이는 통계적으로 확인 안 됨.

## 5. 안 된 것 — 정직하게

| # | 무엇이 | 왜 | 어떻게 했나 |
|---|---|---|---|
| 1 | **적중률로 LightGBM을 못 이겼다** | 표 데이터에서 GBDT 가 강하다는 정설과 일치 | 확률 품질로 주장을 옮김 |
| 2 | **S4 어텐션이 안 됐다** | 3.6만 경주에 파라미터 41.6만개는 과적합. 6~11 epoch 에서 조기 중단 | 채택하지 않음 |
| 3 | **6축 타워가 정확도를 2.3%p 잃는다** | 어떤 가중치에서도 안 무너지게 학습한 대가. 인기도 축이 6분의 1로 희석됨 | 슬라이더 기본값을 인기도 쪽에 실으면 회복 |
| 4 | **하이퍼파라미터를 더 짜내지 못했다** | 18구성 × 2 seed = 36회 돌렸으나 기본 설정을 잡음(±0.5%p) 넘어 이기는 게 없음 | "튜닝 부족이 아니다"를 근거로 확보 |
| 5 | **표본이 작아 1%p 차이를 못 가른다** | valid 1,254경주 → 오차 ±0.85%p | 확률 품질(logloss)로 보완 |
| 6 | **장거리(>1700m)에서 뒤진다** | LGB 35.5 vs S3 32.9 | 표본 152경주라 잡음일 수 있음. 미해결 |
| 7 | **3착 확률이 낙관적이다** | 1착 확률에서 유도한 계산이 현실보다 단순 | 2026-09-08 발견. 보정 미적용 |
| 8 | **육종가(EBV) 데이터가 없다** | 팀 원본에 없음 | 학습 때도 63~86% 결측이라 영향 작음 |
| 9 | **조교 API 승인이 안 났다** | 포털 신청 후 5시간 미승인 | **없어도 무방함을 실험으로 확인** (§7) |
| 10 | **주행습성 피처 5% 불일치** | 원장 재빌드 시 발생. 원인 미상 | 결과 영향은 작아 보이나 미해결 |
| 11 | **사전 예측을 못 해봤다** | 지난 주말은 이미 끝난 경주 | 다음 주말에 사전 공개 예정 |
| 12 | **test 를 안 열었다** | 최종 1회 규칙 | **의도적.** 튜닝 여지 보존 |

## 6. 검증 — 어떻게 믿을 수 있나

숫자보다 중요한 부분이다. 다음을 직접 확인했다.

| 검증 항목 | 방법 | 결과 |
|---|---|---|
| 시간 누수 없음 | train 최종일 vs valid 시작일 | 겹치는 날짜 0, 경주 0 |
| 피처에 정답 없음 | 연속 출전 쌍의 생애 출전수 증가폭 | 9,848쌍 전부 정확히 +1 |
| 생애 승수 갱신 | 직전 경주 결과대로 갱신됐나 | 9,367쌍 100% |
| valid 만 잘 맞지 않나 | 피처-정답 상관을 분할 간 비교 | train +0.168 / valid +0.166 |
| 첫 출전 말 | 전적 항목이 비어 있나 | 632두 전부 결측 |
| 이력 시점 | 코드 assert | 현재보다 뒤 날짜 섞이면 실행 중단 |
| 전처리 기준 | 표준화·어휘·통계 | 전부 train 에서만 fit |

**가중치 선택의 낙관 편향도 스스로 걷어냈다.** 앙상블 비율을 valid 전체로 고르면 35.3 이지만,
valid 를 반으로 갈라 교차 적합하면 34.8 이다. **홍보 숫자는 34.8 을 쓴다.**

## 7. 실경기 예측 (2026-09-07)

팀 데이터셋에 없는 진짜 새 경주를 답 안 보고 예측했다.

**대상**: 2026-08-31 ~ 09-06, 49경주 (배당 있는 경주만)

| 모델 | 1등 적중 | 3착 이내 |
|---|---:|---:|
| 시장 (인기 1위마) | 42.9% | 73.5% |
| **우리 딥러닝 (S3)** | **32.7%** | 63.3% |
| LightGBM 73 | 26.5% | 61.2% |

표준오차 ±6.8%p (49경주라 정밀하지 않음)

| 읽기 | 내용 |
|---|---|
| valid 기대치 재현 | 34.8 → 32.7, 오차 안. **처음 보는 경주에서도 유지된다는 첫 실증** |
| LightGBM 대비 | +6.2%p (valid 에서는 +0.8%p 였음) |
| 시장 대비 | −10%p. 배당을 안 보는 조건이라 예상된 결과 |
| 1등 못 맞혀도 | 우리가 찍은 말이 **3착 이내에 69.4%** 들어감 |
| 시장과 다르게 고른 18경주 | 2회만 적중(11.1%). 단 그 경주는 시장도 7/18 만 맞힌 어려운 경주 |

**부수 성과 — 데이터 파이프라인을 자립시켰다**

| 항목 | 내용 |
|---|---|
| 원장 자체 구축 | KRA API 로 2010~2026, 456,884행, 8분 |
| 검증 | 팀 데이터셋 406,660행과 **착순 100% 일치** |
| 성적표 재빌드 | 팀 빌더 그대로. 피처 65개 중 59개 완전 일치 |
| 증분 갱신 | `uv run python -m ingest.ledger --date YYYYMMDD` |
| API 갱신 시점 | 일요일 경주가 **월요일에 이미 반영** |

**조교 데이터가 필요 없음을 확인** — valid 에서 조교 2칸을 비우고 재측정한 결과
적중률 차이 **+0.00%p** [−0.96, +0.88]. S1 선형에서는 중요도 4위였지만, S3 는
전적 GRU 가 그 정보를 이미 읽는다.
