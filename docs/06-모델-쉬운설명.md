## Q1. 모델을 직접 만드는 건 어렵다. 허깅페이스에서 가져와 파인튜닝하는 게 낫지 않나?

**이 문제에는 가져올 모델이 사실상 없다.**

- 사전학습 모델이 힘을 쓰는 건 언어·이미지·소리처럼 "세상 공통 지식"이 있는 데이터다. 문장 읽는 법, 고양이 모양은 어느 데이터에서나 같으니 미리 배운 게 옮겨진다.
- 우리 데이터는 말 한 마리당 숫자 77개짜리 표다. "기수 승률 0.23이 뭘 뜻하는지"를 미리 배워둔 모델은 없다. 옮겨올 지식 자체가 없다.
- LLM에 표를 문장으로 넣어 파인튜닝하는 방법은 있지만, 이런 숫자 표에서는 LightGBM보다 못한 게 정설이다. "한 경주 12마리 중 누가 1등이냐"를 한 번에 비교하는 구조를 얹기도 어렵다.
- 표 전용 사전학습 모델(TabPFN)은 있다. 한 번에 넣을 수 있는 행이 만 개 안팎이라 train 38만 행을 다 못 먹고, 행 하나씩 분류하는 구조라 경주 단위 순위에 맞지 않는다. 사이드 실험 후보.

**그리고 지금 만든 모델은 "어려운 모델"이 아니다.**

- S1~S4 파라미터가 10만~40만 개, 학습이 10초~1분. GPT 계열 수십억 개와 비교하면 장난감 크기다.
- 시간을 쓴 부분은 모델 구조가 아니라 누수 막기, 시기 분할, 잡음과 진짜 차이 구분이었다. 이건 어떤 모델을 가져와도 똑같이 해야 한다.
- 유일하게 "우리 설계"인 S3의 말별 전적 GRU는 경마 도메인 지식이 들어간 부분이고, 확률 품질에서 LightGBM을 10번 중 10번 이긴 이유다.

## Q2. "valid로 고른 값"이 뭔가?

데이터를 셋으로 나눴다. **train은 교과서, valid는 모의고사, test는 수능.** 수능은 팀이 이미 한 번 봤으니 다시 못 본다.

문제는 모의고사를 두 용도로 같이 썼다는 것.

1. **고르는 데 씀.** "몇 번째 epoch에서 멈출까", "LightGBM과 S3를 몇 대 몇으로 섞을까"를 모의고사 점수 보고 정했다. 5:5가 35.3으로 제일 높아서 골랐다.
2. **점수 내는 데도 씀.** 그 35.3을 결과라고 적었다.

모의고사 열 번 보고 제일 잘 나온 회차를 내 실력이라고 말하는 것과 같다. 조금 부풀려진다.

그래서 모의고사를 반으로 갈라, 한쪽으로 섞는 비율을 고르고 다른 쪽에서 점수를 쟀다. **34.8**이 나왔다. 이게 정직한 기대치고, 홍보 숫자는 35.3이 아니라 34.8을 쓴다. (`experiments/side/ledger_side.md` §3)

### 슬라이더는 과목별 비중

## Q4. 검증이 제대로 된 게 맞나?

2026-09-03에 직접 다시 확인한 결과.

### 튼튼한 부분

- **시간이 안 섞임.** train 2010-01-08 ~ 2025-11-09, valid 2025-11-14 ~ 2026-05-10. 겹치는 날짜 0, 겹치는 경주 0.
- **피처에 답이 미리 들어가 있지 않음.** 같은 말이 valid 안에서 연속 출전한 9,848쌍 전부 생애 출전수가 정확히 1씩 늘었다. 생애 승수도 9,367쌍 전부 "직전 경주 결과대로" 갱신됐다. 현재 경주 결과가 피처에 먼저 반영돼 있으면 이게 깨진다. 첫 출전 말 632두는 전적 항목이 전부 비어 있다(정상).
- **valid에서만 유독 잘 맞는 피처가 없음.** 피처와 1등의 상관이 train/valid에서 같다 (예: 생애 승률 +0.168 / +0.166, 최근 3착순 −0.204 / −0.209).
- **딥러닝 이력도 코드가 매번 검사함.** 과거 전적 텐서에 현재보다 뒤 날짜가 섞이면 assert로 실행이 죽는다 (`pipeline/model/history.py`).
- **전처리 기준값을 train에서만 잡음.** 표준화 평균·편차, 임베딩 사전, 이력 통계 전부 train 기준.

### 약한 부분

- **valid로 고르고 valid로 점수를 냈다.** Q2 참조. 교차적합으로 걷어낸 34.8이 정직한 값.
- **딥러닝 모델은 test를 아직 안 봤다.** test는 팀이 LightGBM으로 한 번 열었고, DL 모델은 한 번도 안 쟀다. 발표 전에 최종 후보 하나만 골라 test를 딱 1회 열어야 "검증 끝"이다.
- **표본이 작아 1%p 차이를 구분 못 한다.** valid 1,254경주면 오차 ±0.85%p. 모든 top-1 비교의 신뢰구간이 0을 품는다. "LightGBM보다 적중률이 높다"는 검증된 게 아니다. 검증된 건 "확률 품질(logloss)이 10번 중 10번 낫다"까지.
- **game ROI는 부풀려짐.** game이 train 날짜 사이사이에 끼어 있어 생긴 문제. 서비스 표기는 valid 값으로.

### 지금 숫자로 할 수 있는 주장

"적중률은 LightGBM과 같은 수준, 확률 품질은 일관되게 낫다." 여기까지.

## Q5. 데이터가 어떻게 생겼나? 말마다 무슨 데이터가 있고, 품질은?

### 한 줄 = 말 한 마리가 어떤 경주에 한 번 출전한 기록

| 파일 | 행 (출전 기록) | 경주 수 | 열 |
|---|---:|---:|---:|
| train | 385,514 | 36,586 | 97 |
| valid | 13,252 | 1,254 | 97 |

97열은 세 종류.

- **식별 10개**: 경주 ID, 날짜, 말 번호·이름, 기수·조교사 번호 등. 모델에 안 들어감.
- **정답 5개**: 착순, 1등 여부, 3착 이내 여부, 스피드지수 등. 경주가 끝나야 아는 값. 모델에 안 들어감.
- **피처 77개**: 경주 출발 전에 알 수 있는 값. 이게 성적표. 나머지 5열은 팀 채점기가 제외한 열.

경주당 5~16두(중앙값 10). 말 한 마리는 train에서 평균 13.5번, 최대 200번 출전.

| 항목 | 값 | 뜻 |

| F1_starts_life / win_rate_life | 3 / 0.33 | 생애 3번 뛰어서 1승 |
| F1_ord_avg3 | 2.0 | 최근 3경주 평균 2등 |
| F1_layoff_days | 14 | 지난 경주 후 14일 쉼 |

말마다 같은 77칸이 있지만 칸이 다 채워져 있진 않다.

### 품질: 비어 있는 칸이 많고, 이유가 셋

| 어떤 칸 | train 결측 | valid 결측 | 왜 비었나 |
|---|---:|---:|---|
| F2 육종가 8개 | 63~86% | 26% | 2016년 이전엔 육종가 자체가 없었음 |
| X_rating | 57% | 25% | 같은 이유 |
| F2 아비말 정보 | 52% | 14% | 같은 이유 |

**비어 있는 게 랜덤이 아니라 정보다.** "육종가 없음"은 옛날 말, "조합 승률 없음"은 처음 타는 기수라는 뜻. 그래서 채우기만 하면 안 되고 "비어 있었다"는 표시를 따로 남긴다(Q6 ②).

가짜 결측도 있다. 아비말 ID에 `-`가 12,011건 들어 있어 결측 검사에 안 잡히고, 등급 표기가 `국5등급`과 `국5`로 섞여 있다. LightGBM과 조건을 맞추려고 일부러 안 고쳤고, 딥러닝 쪽에선 임베딩 사전에서 "모르는 값"으로 흡수된다. (팀 EDA `docs/eda/report.html`, PR #1 설명에도 같은 진단이 있다.)

## Q6. 코드가 이 표를 어떻게 "말 점수"로 바꾸나 — 단계별

`pipeline/model/data.py`와 `losses.py` 두 파일이 전부. 여섯 단계.

**① 읽기** (`data.py` `load`)
팀 채점기로 읽는다. 배당 없는 경주는 빼고, 같은 경주 말들이 붙어 있도록 정렬 검사. 73피처면 인기도 4개를 뺀 것, 77이면 포함.

**② 숫자 다듬기** (`data.py` `fit_encoder`, `transform`)
열마다 단위가 제각각이다. 승률은 0~1, 상금은 700만, 나이는 3. 그래서 열마다 **"평균보다 몇 단계 위인가"**로 바꾼다. train에서 평균·편차를 재고 valid는 그 기준을 그대로 쓴다.

```python
median = tr[numeric].median()          # 빈 칸은 train 중앙값으로 채움
na_flag = na_rate[na_rate > 0.2]       # 20% 넘게 비는 열은 "비어있었음" 표시 열을 따로 추가
z = (num.fillna(median) - mean) / std  # 평균 0, 편차 1 로 변환
z = np.clip(z, -8, 8)                  # 극단값 잘라냄
```

날씨·성별·산지 같은 글자 열은 값마다 0/1 칸으로 펼친다. 그래서 73열이 153칸이 된다. 가중치 표에 `F4_weather=맑음`이나 `F2_ebv_ssgblup#na`가 있는 이유.

**③ 경주 단위로 묶기** (`data.py` `pack_races`)
경마 문제의 핵심. 말 한 마리씩 보면 안 되고 **같은 경주 말들을 한 상자에** 넣어야 한다. 경주당 최대 16두라 상자는 16칸, 10두 경주면 6칸이 빈 채로 mask가 0. 상자마다 "1·2·3등이 몇 번 칸인지"를 정답으로 같이 넣는다.

```
x     [경주 수, 16칸, 153숫자]   ← 성적표
mask  [경주 수, 16칸]            ← 1이면 진짜 말, 0이면 빈 칸
order [경주 수, 3]               ← 1·2·3착이 몇 번 칸인지
```

**④ 점수 매기기** (`models.py` `LinearRanker`)
제일 단순한 S1은 이 한 줄. 153숫자 × 153가중치를 곱해 더한 게 점수.

```python
self.w = nn.Linear(dim, 1, bias=False)   # 가중치 153개
return self.w(x).squeeze(-1) * mask      # 점수 = 성적표 · 가중치
```

S2~S4는 이 곱셈을 여러 층 겹치고, 말별 과거 20경주를 순서대로 읽는 부품이 붙는 것뿐.

**⑤ 배우기** (`losses.py` `plackett_luce`)
가중치를 어떻게 정하냐가 "학습". 규칙은 하나.

> 경주 안에서 점수를 확률로 바꿨을 때 **실제 1등 말의 확률이 높아지도록** 가중치를 조금씩 고친다. 1등을 빼고 나머지 중 실제 2등의 확률이 높아지도록 또 고친다. 3등까지.

```python
masked = scores.masked_fill(avail == 0, NEG)   # 빈 칸과 이미 뽑힌 말은 제외
logZ = torch.logsumexp(masked, dim=1)          # 경주 안 확률의 분모
chosen = scores.gather(1, idx)                 # 실제 k등 말의 점수
total += (logZ - chosen)                       # 이 값이 작을수록 실제 k등 확률이 큼
```

36,586경주에 대해 반복하면 "초반 위치 −0.24, 나이 −0.16" 같은 숫자가 저절로 나온다. **1등 말들이 공통으로 가진 특징에 무게가 실린 결과.**

**⑥ 채점** (`evaluate.py`, 팀 채점기)
valid 1,254경주마다 모델이 1위로 찍은 말이 실제 1등이면 적중. 그 비율이 top-1. 확률까지 보는 게 logloss.

## Q7. 그래도 베이스가 된 모델은 있을 것 아닌가? 무슨 기반으로 어떻게 만들었나?

"베이스 모델"을 두 가지로 나눈다. **사전학습된 가중치를 가져온 건 없고, 부품과 방법론은 다 기존 것이다.**

### 기반: PyTorch, GPU 학습

| 항목 | 값 |
|---|---|
| 프레임워크 | PyTorch 2.14 (CUDA 13) |
| 학습 장치 | RTX 4070 Laptop 8GB |
| 비교 기준선 | LightGBM 4.7 (팀 코드 그대로 재현) |
| 최적화기 | AdamW + OneCycle 학습률 스케줄, gradient clip 1.0 |
| 손실함수 | Plackett–Luce (경주 단위 순위 확률) |
| 재현성 | seed 고정, `torch.use_deterministic_algorithms` |

### 부품은 전부 PyTorch 표준 레이어

직접 만든 건 "부품을 어떻게 조립하느냐"고, 부품 자체는 PyTorch에 들어 있는 것을 그대로 쓴다. `pipeline/model/models.py`.

| 단계 | 쌓은 부품 | 부품 출처 | 역할 |
|---|---|---|---|
| S1 linear | `nn.Linear` 1개 | PyTorch | 153가중치 곱셈. Q3의 가중치 표 |
| S2 embed | `nn.Embedding` 3개 + `nn.Linear` 3층 | PyTorch | 기수·조교사·아비말 ID를 16차원 벡터로 |
| S3 history | S2 + `nn.GRU` 1개 | PyTorch | 말별 과거 20경주를 순서대로 읽음 |
| S4 attn | S3 + `nn.TransformerEncoder` 2층 | PyTorch | 같은 경주 말들이 서로를 봄 |
| S5 tower | `nn.Linear` 3층 × 6축 + Dirichlet 샘플링 | PyTorch | 슬라이더용 6과목 점수 |

GRU는 2014년, Transformer는 2017년에 나온 구조. 우리가 발명한 게 아니라 조립한 것.

### 방법론도 기존 것

- **S1의 정체는 조건부 로지스틱 회귀.** 경마 예측에서는 1994년 Bill Benter가 홍콩 경마로 정립한 방식이고, 그 뒤 경마 논문 대부분이 이걸 기준선으로 쓴다. `models.py` 주석에 "Benter 방식"이라고 적혀 있다.
- **손실함수 Plackett–Luce**는 1975년 통계 모형. "1등 뽑고, 빼고, 2등 뽑고"를 확률로 쓴 것. 검색 순위 학습(learning to rank)에서 ListMLE라는 이름으로도 쓴다.
- **6축 타워의 Dirichlet 랜덤 가중치**는 다목적 학습 기법. 유저가 어떤 비중을 넣어도 무너지지 않게 학습 중 비중을 매번 무작위로 뽑는다.

### 그래서 "모델을 만들었다"의 정확한 뜻

- **가져온 것**: PyTorch 레이어, Benter의 조건부 로지스틱, Plackett–Luce 손실, GRU·Transformer 구조.
- **우리가 한 것**: 경마 데이터에 맞게 **입력을 설계**하고(77칸 성적표, 경주 단위 상자, 말별 이력 텐서), 부품을 **네 단계로 조립**해 각 단계가 뭘 더하는지 재고, **누수 없이 검증**한 것.

### 발표용 한 문단

> PyTorch 표준 레이어로 경마 예측의 고전 방식(Benter 조건부 로지스틱)을 먼저 재현하고, 그 위에 말별 전적을 순서대로 읽는 GRU를 얹었습니다. 사전학습 모델은 이 데이터에 해당하는 게 없어 쓰지 않았고, 학습은 노트북 GPU에서 단계당 10초에서 1분입니다.

"허깅페이스 모델 파인튜닝"과의 차이는 가중치를 남이 학습한 것에서 시작하느냐, 0에서 시작하느냐다. 우리는 0에서 시작했고, 데이터가 36,586경주라 그걸로 충분했다. 파라미터 10만~40만 개 모델은 이 규모에서 몇 초면 수렴한다.
