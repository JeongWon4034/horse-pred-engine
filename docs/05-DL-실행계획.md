## 1. 왜 이 순서인가

- LightGBM 기준선은 팀 레포 `docs/model/` 에 이미 있다(이도연, 커밋 `cb06601`). **다시 돌리지 않는다.** DL 을 같은 하네스에 꽂아 같은 표에서 비교한다.
- 스펙(`horse-racing-ai-spec.md`) 3-1 의 단계 순서를 지킨다: 선형 → 범주형 임베딩 → 과거 전적 시퀀스 → 경주 내 attention. 어느 단계에서 오르고 어디서 안 오르는지가 곧 발표 자료다.
- 나중에 Airflow 와 블록체인이 붙는다. 각 단계는 CLI 하나 + parquet 산출물로 잘라 둔다 (§5).

### 넘어야 할 선 (팀 측정, valid 1,254경주, top-1 표준오차 ±0.85%p)

| 모델 | 피처 | top-1 | top-3 |
|---|---|---:|---:|
| 시장 (인기 1위마) | — | 39.3 | 69.3 |
| LightGBM (lambdarank, 200라운드) | 77 (인기도 포함) | 38.9 | 68.1 |
| **LightGBM** | **73 (인기도 제외)** | **34.0** | 63.2 |
| 무작위 | — | 10.2 | 30.8 |

test(796경주)는 팀이 이미 1회 열었다: 시장 36.1 / LGB77 36.1 / LGB73 31.7. **다시 열지 않는다.**

- 주 비교축: **73피처(인기도 제외)** — 주말 실시간 조건. DL 이 "이겼다"고 쓰려면 valid top-1 **≥ 35.7** (34.0 + 2×SE). 미만이면 "차이 없음".
- 부 비교축: 77피처(게임 모드, 6축 슬라이더용). 시장 39.3 을 넘는 건 기대하지 않는다(확정배당이라 시장이 이미 경주 후 정보를 안고 있다). 여기서 보는 건 logloss·캘리브레이션·축 분해.
- 사전 전망: top-1 에서 DL 이 GBDT 를 크게 이길 확률은 낮다. 우위가 나온다면 **S3 전적 시퀀스**와 **S4 attention**, 그리고 top-3 / logloss / 혼전 경주에서 나온다. 져도 단계별 수치가 결과다.

## 2. 고정 규칙

- 데이터 읽기·피처·평가는 **팀 하네스로만**: `C.load()` (= `schema_v2.clean()` + `usable()` + 정렬 검사), `C.feature_cols(exclude_pop=True|False)`, `C.report()`. 다른 방식으로 재지 않는다.
- game 3,700경주는 학습·검증·튜닝 금지. ROI 백테스트에만 쓴다. 배당 `9999.9` 는 `clean()` 이 NaN 으로 바꾼다.
- 셔플은 경주끼리만. test 재개봉 금지. seed `20260901`.
- 실험마다 `experiments/ledger.md` 에 한 줄 (커밋·데이터 기준 커밋·피처 세트·지표).
- 커밋·코드·주석·문서에 AI 도구 흔적 금지 (로컬 작업 지침 참조). 푸시 전 `git log -3 --format=%B` 를 확인한다.
- 브랜치: `feat/dl-stages` (← `feat/data-ingest`). `PR_BODY.md` 는 그대로.
- 콘솔 출력은 `PYTHONUTF8=1` (`.vscode/settings.json` 터미널 env 에 넣어 뒀다).
- torch CUDA 전환: `uv add torch --index https://download.pytorch.org/whl/cu130` 시도. Python 3.14 휠이 없으면 `uv python pin 3.12` 후 `.venv` 재생성. CPU 여도 110만 파라미터 · 3.6만 경주라 학습 가능하다.

## 3. Phase 0 — 남은 기반 작업 (반나절)

1. **`data.py` 를 하네스 위로 옮긴다.** `load()` → `team.C.load(split)`, 피처 목록 → `team.C.feature_cols(...)`. `ONEHOT`/`HIGH_CARD` 는 `schema_v2` 의 dtype 정의와 맞춘다. 비활성 5개(`F1_prize_life*`, `F4_hr_meet_win_rate`, `F4_month`)는 `feature_cols()` 가 이미 뺀다.
2. **`evaluate.py` 정리.** top-1/top-3 는 `C.report()` 로 대체. 남기는 것: 1착 logloss(경주 내 softmax NLL), ECE(기존 `expected_calibration_error`), Brier. 추가: **경주별 hit 벡터 + paired bootstrap** `compare(a, b, n=2000)` → 차이의 95% CI. "차이가 있는가"의 판정 도구. 입력은 행 단위 점수 배열(하네스 규약)로 통일해 LGB 예측과 DL 을 같은 함수에 넣는다.
3. **기준선 재현 1회.** `PYTHONUTF8=1 uv run python data/model/baseline_lgbm.py` → 38.9 / 34.0 이 ±0.3 안에 나오는지. 안 나오면 사본 문제이므로 멈춘다. 예측 점수는 `experiments/pred/lgb_{73,77}.parquet` 로 저장해 이후 paired 비교에 쓴다.
4. **ROI 백테스트** `pipeline/model/backtest.py`(신규): game pool `game/entries.parquet`(winOdds) + `payouts.csv` 단승 → 모델 1위마 단승 1단위 ROI · 평균 배당. 스펙 §3.2 온보딩 프리셋의 실측치가 여기서 나온다.

## 4. Phase 1 — 스펙 3-1 순서대로 DL 4단계 (2~3일)

재사용: `losses.py`(`plackett_luce`, `win_probabilities`), `data.py`(`Encoder`, `to_races`, `tower_slices`, `MAX_FIELD=16`), `models.py`(`LinearRanker`, `TowerRanker.sample_weights` Dirichlet α=0.7, 경주 내 z-score), `train.py`(OneCycle, 경주 단위 셔플).

**모든 단계를 73피처(주) · 77피처(부) 두 번 돌린다.** `uv run python -m model.train <kind> [--market]`. 손실은 S1~S4 `plackett_luce(topk=1)` (LGB 와 같은 정의의 1착 logloss), S4 에서 `topk=3` 변형 1회 추가.

| 단계 | 구성 | 신규 파일 | 확인할 것 |
|---|---|---|---|
| **S1** | 수치 피처 + 선형 → 경주 내 softmax | (기존 `LinearRanker`) | 하네스로 재측정. 73피처에서 LGB 34.0 근처면 파이프라인 정상 |
| **S2** | + 범주형 임베딩 `jkNo` `trNo` `F2_sire_id` (각 16차원, 등장 5회 미만 `<rare>`, 미등장 `<unk>`, train 에서만 fit) | `model/categorical.py`, `EmbedRanker` | 팀 README 의 "범주형 native 처리 29.2%(악화)" 가 임베딩에서도 재현되는가. **말 ID(`hrNo`) 임베딩 금지** |
| **S3** | + 과거 전적 GRU: `hrNo` 별 `rcDate` 정렬, `rcDate < 현재` 인 직전 ≤10출전 `[R,16,10,k]` (착순 백분위·`y_speed_fig`·거리·거리차·휴양일·부담중량·등급·기수 교체). `nn.GRU(k,64)` | `model/history.py` | **가장 기대되는 단계.** ablation: F1 집계 피처 제거 + GRU 만 → 시퀀스가 평균 뭉개기보다 나은가. 시점 누수는 assert 로 차단. **game 행은 이력에서 제외**(2015~24 에 15% 구멍 — 장부에 명기) |
| **S4** | + 경주 내 self-attention: `TransformerEncoderLayer(d=128, nhead=4, ff=256, dropout=0.2, norm_first=True, batch_first=True)` ×2~3, **positional encoding 없음**, `src_key_padding_mask` | `RaceTransformer` (`models.py`) | **핵심 숫자.** S3 대비 paired CI 가 0 을 벗어나는가. 보조: `F6_field_entropy` 3분위별 top-1(혼전 경주에서만 앞서는지), 등급·거리별 분해. 안 오르면 시간 분할·가중치 샘플링(이 단계엔 없음이 정상) 확인 후 "차이 없음"으로 적고 S4+LGB 앙상블(logloss)로 방향 전환 |
| **S5** | 6축 헤드 + 종합 헤드 1(가중치 1 고정) + Dirichlet 랜덤 가중치. 77피처 전용(게임 모드). 손실 `topk=3` | `model/score.py` (점수 캐시 출력) | 축 단독 top-1 바닥 ≥ 25%, **축 간 예측 상관 ≤ 0.9**, 균등 가중 vs 종합 헤드 격차, game ROI(프리셋 3종: 안정형/이변형/사람파). 산출 `experiments/scores/{split}.parquet` = race_id · hrNo · 6축 z-score · 종합 · `content_hash` |

스펙과 데이터의 차이(장부에 명기): 모마 컬럼이 없어 혈통 임베딩은 부마만. 구간 통과(`sim/passing`)는 학습 금지 데이터라 F5 는 주어진 `F5_*` 컬럼만 쓴다.

## 5. Phase 2 — 비교표 · 반출 · 확장 여지

1. valid 표(73/77 각각): 시장 / LGB / S1 / S2 / S3 / S4 / S5 — top-1, top-3, logloss, ECE, game ROI, LGB 대비 paired 차이·CI. `C.report()` 출력을 그대로 붙인다.
2. `experiments/report.md`: 표 + 결론(지표별로 "이겼다/비겼다/졌다" 분리) + 스펙 §9 Q&A 답.
3. 익으면 팀 레포로: `docs/model/model_dl.py` 를 `model_dl_template.py` 인터페이스(`MyModel.predict(df, cols)` → 행 순서 점수)로 맞춰 MR. 브랜치 `feat/model-dl` ← `origin/develop`.
4. **Airflow 대비**: 각 단계를 순수 CLI 로 — `model.train <kind>`, `model.score --split game`, `model.backtest`. 입력 parquet → 출력 parquet/json, 멱등. DAG 는 주간 `sync → train → score → backtest` 4태스크 래핑.
5. **블록체인 대비**(팀 `RacePool.sol` 초안): 올릴 것은 모델이 아니라 **점수 캐시 해시 + 유저 가중치 프로필 해시**(시즌 기록 불변성). `scores/*.parquet` 의 `content_hash` 가 앵커.

## 6. 검증

- 기준선 재현이 팀 표 ±0.3%p.
- 각 단계 `train.py` 로그 = 장부 = `C.report()` 출력. DL 과 LGB 의 경주 수 `n` 동일.
- 이력 텐서 `rcDate < 현재` assert, game ∩ 이력 = 0.
- 같은 명령 2회 실행 시 top-1 차이 < 0.1%p.
- 푸시 전 AI 흔적 grep 빈 출력. 세션 끝에 마스터 노트 로그 한 줄.
