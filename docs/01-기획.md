# 01 · 기획 확정

## 앱 성격 — B안 (예측 대결)

컨설턴트 피드백의 핵심이 **"포트폴리오와 론칭을 둘 다 잡으려 한다"**였고, 그게 맞았다.
선택지는 사실상 둘뿐이었고 **B로 확정**.

| | A. 입문자 가이드 | **B. 예측 대결 (채택)** |
|---|---|---|
| 하는 일 | 경마장 처음 간 사람이 이해하게 | 예측 실력 겨루기 |
| 개인화 | 불필요 — 정답 하나 주면 끝 | **필수 — 성향이 곧 게임** |
| 포인트 | 없음 | 순위용, **환금성 0** |
| 3D | 없음 | 경기 후 실제 기록 재생 |
| 기존 서비스와 차이 | 거의 없음 (경마선생·신마신·마패가 이미 A) | **아무도 안 함** |
| 포트폴리오 | 약함 | 강함 |

**A로 가면 우리의 유일한 차별점이 사라진다.** 후발주자로 같은 걸 만드는 셈이고,
6주 뒤에 남는 게 "AI 예측 앱 하나 더"가 된다.

### 탭 구조

```
예측 대결 (메인)   ← 개인화 · 우리만의 것
정보 탭  (보조)    ← 용어·입문 가이드. A안을 여기로 흡수
게임 탭  (삭제)    ← 미니게임/육성. 성격 흐림 + 작업량 큼
```

`poc/race/js/pet.js` 계열 작업은 중단. 성격도 뚜렷해지고 작업량도 크게 준다.

## 개인화 정당성 (5번 반복해서 지적받은 부분)

> **"과거 데이터 기반이면 왜 개인화가 되어야 할지 모르겠음. 모두가 인풋값이 같은데 왜?"**

**조건부로 맞는 지적이다.** 조건이 뭔지가 핵심.

| 정답이 있음 (모델이 푼다) | 정답이 없음 (사람이 고른다) |
|---|---|
| 어느 말이 빠른가 | **자주 맞힐까, 크게 먹을까** |
| 최적 가중치는 뭔가 | **나는 어떤 관점을 믿나** |
| 어떤 피처가 유의한가 | 어떤 상황에 특화된 에이전트를 만들까 |

**"자주 맞히기 vs 크게 먹기"는 걸린 게 있어야 의미가 생긴다.**
배당이 없으면 트레이드오프 자체가 존재하지 않고, 그럼 최적 답 하나만 주는 게 맞다.

→ **개인화가 말이 되냐는 앱 성격이 정한다. B를 골랐으므로 성립한다.**

### 그리고 이 질문은 백테스트로 답이 나온다

> "우리가 설계한 디폴트 모델이 우수할 것인가, 가중치 준 게 더 우수할 것인가,
> 사람 개입이 도움이 될까?"

거의 확실히 이렇게 나온다:

```
최적 가중치 (학습이 찾은 것)   적중률 33%   평균배당 3.1배
프리셋 안정형                  적중률 31%   평균배당 4.2배
프리셋 이변형                  적중률 22%   평균배당 9.8배
```

**사람 개입은 평균 적중률을 낮춘다. 그게 맞다.**
근데 그건 우리 주장과 모순이 아니다 — 파는 게 "더 정확함"이 아니라 **"성향을 고를 수 있음"**이니까.

**발표에서 이렇게 말한다:**

> "유저 개입은 평균 적중률을 3%p 낮췄지만 평균 배당을 2.1배 올렸습니다.
> 우리가 판 건 정확도가 아니라 선택권입니다."

숨기면 무너지고, 드러내면 설계 의도가 된다.
→ UI 원칙: **적중률과 평균 배당을 항상 나란히.** 적중률만 보이면 전원 안정형 고르고 게임 끝.

### 정직한 표현

유저가 하는 건 "모델을 만드는 것"이 아니라 **"모델을 고르는 것"**이다.
UI에서 "나만의 AI 모델 만들기"라고 쓰면 과장. **"나만의 분석가 만들기"**가 정직하고 더 잘 읽힌다.

### 프리셋 3종 (6종에서 축소)

| 에이전트 | 대사 | 배분 (100AP) |
|---|---|---|
| **안정형** | "자주 맞히는 게 중요하죠" | 최근성적 35 · 인기도 30 · 거리날씨 20 · 기수 15 |
| **이변형** | "남들이 못 보는 걸 봅니다" | 주행 35 · 거리날씨 30 · 부모 20 · 최근성적 15 · 인기도 0 |
| **사람파** | "결국 타는 사람 차이죠" | 기수 40 · 최근성적 25 · 인기도 20 · 거리날씨 15 |

- 인기도 비중을 **0~30으로 크게 벌린다** → "시장을 얼마나 믿을 것인가"를 첫 선택에서 고르게
- 표시 수치는 **백테스트 실측값**으로 교체 (추정값 금지)
- 안내 문구 필수: *"적중률이 높다고 더 좋은 건 아니에요. 자주 맞히는 대신 적게 먹거나, 드물게 맞히고 크게 먹거나의 차이입니다."*
- **"언제든 바꿀 수 있어요"** 명시 — 돌이킬 수 없어 보이면 이탈

## 3D 화면 — 경기 후 재생만

실시간 렌더링은 불가능(위 참조). 유일하게 가능한 흐름:

```
예측 제출 (경기 전) → 실제 경기 발주 → 결과·구간기록 수집
                                            ↓
                              실제 기록으로 3D 재생 + 채점
```

가짜가 하나도 없고, 구간기록 API가 있으니 데이터도 진짜다.
"내가 찍은 말이 어떻게 달렸는지" 보는 게 채점 화면으로 자연스럽다.

## 컨설턴트 피드백 대응 정리

### 옳은 지적 (수용)
1. **앱 성격을 픽스해라** → B안 확정
2. **둘 다 잡으려 한다** → 게임 탭·환금성 삭제
3. **개인화가 정당한지 스스로 답해라** → 위 논거 + 백테스트로 실증
4. **에이전트 6개는 많다** → 프리셋 3종
5. **성능 시나리오 미리 설계** → 캐시 구조 + 예상 트래픽 문서 작성
6. **일본 서비스 참고** → 조사 예정
7. **유료 예측 위법성** → 환금성 0으로 회피

### 오해인 지적 (설명 필요)

| 지적 | 실제 |
|---|---|
| "랭체인·랭그래프 쓰면 된다" | 그건 **LLM 오케스트레이션 도구**. 우리는 랭킹 모델을 직접 학습시킴 — 다른 영역. 정보 탭 RAG에만 해당 |
| "8초 걸린다, 큐 넣어야" | LLM 호출 가정한 숫자. 우리 구조는 **축 점수 캐시 + 곱셈 6번 = 60ms**. 유저 100명이든 1만명이든 모델 재실행 없음 |
| "실시간으로 말 달리는 렌더링" | KRA API에 경주 중 위치 데이터 없음. **제약이지 결정이 아님** |

→ 다음 미팅에서 **캐시 구조 그림 한 장**으로 2번은 해소된다.

```
축 점수 s₁~s₆  ← 미리 계산해서 캐시 (경기당 1회)
       ↓
유저 슬라이더  → w₁·s₁ + … + w₆·s₆  → 60ms
```

## LangChain / LangGraph의 자리

**주연이 아니라 조연.** 순서를 틀리면 모델 만든 게 묻힌다.

```
      [ 우리가 만든 것 ]                [ 빌려 쓰는 것 ]
   랭킹 모델 (PyTorch 학습)   ←도구로→   LLM 에이전트 (LangGraph)
   포트폴리오 앞면                       서비스 편의 기능
```

- ✅ "랭킹 모델을 직접 만들었고, 그 위에 LangGraph로 대화 인터페이스를 얹었다"
- ❌ "LangGraph로 AI 에이전트를 만들었다"

### 넣을 곳

| # | 기능 | 구성 |
|---|---|---|
| 1 | **대화형 분석가 튜닝** | 도구 3개(가중치 설정 / 백테스트 / 예측) + 대화 루프. 자연어 슬라이더의 완성형 |
| 2 | **경기 후 해설** | 결과 조회 → 기여도 계산 → 문장 생성. 일직선 파이프라인이라 입문용으로 적합 |
| 3 | **주간 리포트** | 출전표 조회 → 내 분석가로 예측 → 요약 |
| 4 | **경마 용어 Q&A** | RAG. 있으면 좋고 자랑거리는 아님 |

**철칙: LLM은 확률 숫자를 절대 직접 만들지 않는다.**
숫자는 항상 도구(모델)가 내고, LLM은 도구를 고르고 결과를 말로 바꾸는 역할까지만.

## ⚠️ 우리 기획과 충돌하는 것

### 55개 항목 슬라이더 — 차별점이 사라진다

설계서가 마패(MapAI) 구조를 그대로 가져왔다 —
5개 그룹(기본 / 기수·조교사 / 스피드지수 / 초반전개 / 후반전개) × 55개 항목.

**그런데 MapAI 조사 후 우리가 내린 결론은 정반대였다:**

> 마패는 55개 손잡이를 다 열어놨다. **55개는 초보가 못 만진다.**
> **"55개를 6축으로 묶어 초보도 쓸 수 있게 한다"** 가 우리 차별점.

55개를 그대로 쓰면 **마패의 열화판**이 된다. 게다가 우리 6축 중 두 개가 통째로 사라졌다:

- **혈통(부모) 축** — 신마 대응의 유일한 정보원
- **인기도 축** — "시장을 얼마나 믿을 것인가"라는 온보딩 핵심 질문이 없어짐

**절충안:** "기본 8개 노출 + 47개 펼치기"에서 **그 8개를 우리 6축(+2)으로 잡고**,
47개는 고급 모드로 접어둔다. 기본 화면은 6축, 파고들면 55개.

### 데이터로 확보 불가능한 항목

설계서 미확정 항목 *"마패 55개 항목의 실제 피처 정의 및 데이터 확보 범위"* 가
지금 가장 급한 미확정이다. UI를 다 그려놨는데 데이터가 없으면 화면을 다시 그려야 한다.

| 항목 | 상태 |
|---|---|
| **스피드지수** | 마패 자체 개발 지수. KRA가 안 줌 → **우리가 직접 계산** (기록 ÷ 거리·주로 표준화) |
| **초반/후반 예측속도** | 구간기록 API 필요. **신청 목록에 없음** |
| **전문가 인기도 · 문자예상** | 예상지 업체 데이터. 공공 API에 없음 → **빼야 함** |

→ `probe` 결과가 55개 중 몇 개가 실제로 가능한지 결정한다.
